# Student previs implementation decisions

22 October 2026. These record technical defaults used during implementation;
accepted user answers and remaining policy clarifications are in `STUDENT_PREVIS_QUESTIONS.md`.

| Decision | Reason / evidence | Remaining qualification |
| --- | --- | --- |
| Independent Vite entries inside the existing app workspace | Admin remains unchanged as an authoring interface; `/student/` uses its own bootstrap/state/database and imports no admin stores. Normal and isolated builds pass. | The student page is a foundation workspace; real scene authoring still needs integration. |
| Client generates the private draft capability before creation | A device-held 256-bit capability, cloud UUID and frozen request are durably committed before network I/O. Lost creation responses can be replayed without recovering plaintext authority from the server. Actual D1/R2/IndexedDB tests pass. | Changes the plan's suggested server-returned capability flow. Separate private recovery is accepted; its UI is still unimplemented. |
| Separate portable edit revision and server revision | Offline edits may coalesce. Server revision starts at zero; exact If-Match and stable request IDs protect writes. Ack metadata includes the exact portable revision. | No collaborative merge; conflicts preserve a local recovery copy. |
| Pinned software AAC for MP4 | Native macOS AAC measured 44 ms delay; software AAC measured 21.35 ms and passed the 40 ms tolerance for all 900 synthetic clicks. Versions pinned to 1.62.0. | Target browser/OS matrix and independent GUI players remain pending; this does not promise sample-perfect AAC timing. |
| Full existing raster post stack in the short diagnostic | GTAO/SSR/bloom/SMAA pass real WebGPU export checks with single-sample depth. `?raw` provides a comparison path. | User accepted framing/exposure/visible LED with admin raster appearance; additional DOF/LED illumination simulation is not required at launch. Full real-scene integration remains. |
| Reference-free backup foundation only | Unknown teacher asset/base-scene versions cannot honestly be acknowledged as fully backed up. The service keeps them pending until catalogue/media verification exists. | Current student UI is not connected to the API. No hosted backup or share claim. |
| Built shell caching only | Precache only the student entry's static dependency graph. Real offline refresh, exact local edit recovery, safe waiting updates and negative route tests pass. | No model/video caching or offline media readiness claim. |
| Local backend limits are development configuration | 1 MiB JSON, 16 MiB narration object, 10,000 revisions, 100 media objects and 30 creations/minute bound local tests/runtime. No expiry is invented. Hosted environments are disabled. | These are not approved school quotas/retention policy. Streaming/resumable media and production rate controls remain. |
| Independent narration track (user answer supersedes earlier default) | New audio clips default to sequence anchors; shot reorder/resize/delete leaves them unchanged. Atomic explicit mixed-selection movement and legacy detach commands are tested. Original recording assets survive trim/delete. | Existing explicit clip anchors retain old semantics until detached. Audio beyond the visual sequence remains inactive/recoverable; tail behaviour and recording UI remain. |
| Fixed 25 fps and 22,500-frame maximum | Editing, schema and API validation use the same boundary; deterministic export tests hit the full 900-second boundary. | Confirmed hard limit by user; no warning-only mode. |
| 50% black framing bars | Shared student preview/export compositing preserves the full 1080p image; 4:3 uses 240-pixel side bars and 2.40:1 uses 140-pixel top/bottom bars. Exact Canvas2D and decoded H.264 pixel checks pass. | Diagnostic integration is complete; production student scene UI/export remain. |
| Shared-password admin and Australia-only access | User chose no admin accounts and an Australia-only audience. Server-side sessions and trusted country metadata protect the edge boundary; local development exemption is explicit. | No deployment; hosted routing/secrets and storage policy remain gates. |
| Base M5 target | Host reports Apple M5, Mac17,2, 10 CPU cores and 16 GiB RAM. Existing and current local Chrome proofs run on this machine. | Real-scene long export and remaining browser/OS/player matrix pending. |
| Explicit versioned LED presentation | New `presentationVersion: 1` records retain nits, mapped display node, authored UV surface and baked rectangle placement. Legacy v1 brightness/transform semantics remain intact. | New viewers reject legacy presentation explicitly; no silent reinterpretation. Unknown teacher media remains unverified. |
| Portable raster appearance | Preserve the existing fixed GTAO/SSR/bloom/SMAA stack and actual raster background/tone controls. Saturation remains explicitly path-only. | Unknown enabled appearance, automatic exposure and unsupported ground effects still reject. |
| Byte-verified local fixture registry | Studio/SUV/mannequin/LED bytes and glTF-index node mappings are verified before parsing; source locations remain host-only. | This local registry does not authorize teacher catalogue publication or online-backup acknowledgement. |
| Stable raster GPU resources across cuts | Actual-scene repeated exports exposed retained light/shadow UUID and mannequin attribute churn. Reuse raster proxies and owned pose attributes; measured GPU resource counters now stay unchanged. | Short warmed export retained JS grows by 3.56 MB; counters do not establish total process memory. Long-run evidence is recorded separately. |

Shared engine changes remain within `RealtimeRenderer`: optional physical output size in `render({width,height})`, explicit `setEnvironment(texture|null)` to clear stale HDRI fallback state, and stable raster light-proxy/shadow/target identity during synchronization. The latter removes measured shader/uniform cache growth across repeated shot cuts; regression tests preserve light parameters, power conversions, shadow selection and canonical values. Existing admin call signatures remain unchanged. No upstream upgrade, push, release or hosted deployment was included.
